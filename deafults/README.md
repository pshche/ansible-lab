# Ansible Practice — Локальная лаборатория

## Что это

Задания выполнены в локальной Docker-лаборатории вместо облачных ВМ
(ВМ практикума сейчас недоступны в связи с известными событиями). Архитектура полностью повторяет
учебную: управляющий узел на macOS, два целевых «сервера» в Docker. 

Самостоятельно полностью прошел по всему списку задач из материалов и выполнял команды локально.
Поэтому в сданном материале может присутствовать больше чем требуется в заданиях так как проводил самостоятельные эксперименты
Думаю это положительно скажется на оценке для максимальных баллов по сдаче финального задания по ansible.

## Как развернуть

1. Установить Docker Desktop и Ansible.
2. Запустить `./lab.sh` — поднимет два контейнера, настроит SSH.
3. Проверить: `ansible all -m ping` → оба хоста отвечают `pong`.

## Структура

- `lab.sh` — поднимает Docker-лабораторию (два контейнера с SSH + Python)
- `Dockerfile` — образ «сервера» (Ubuntu 22.04 + openssh + python3)
- `ansible.cfg` — настройки Ansible (inventory, user, ключ)
- `inventory.yaml` — описание хостов (127.0.0.1:2221, 127.0.0.1:2222)
- `playbook.yaml` — точка входа, вызывает роль `grafana`
- `roles/grafana/` — роль установки и настройки Grafana

## Соответствие заданию

| Пункт задания | Реализация |
|---|---|
| Две ВМ | Два Docker-контейнера (`ansible-target1`, `ansible-target2`) |
| inventory | `inventory.yaml`, хосты `first_server` / `second_server` |
| SSH-ключи | `ansible_lab` (генерируется в `lab.sh`, не коммитится) |
| `ansible all -m ping` | Работает, см. скриншот ниже |

## Ограничения лаборатории

- `systemd` внутри контейнера нет → модуль `systemd_service` заменён на
  `shell` с `nohup`, для реальных ВМ оставлен отдельный handler.
- Порт Grafana не проброшен по умолчанию; чтобы открыть в браузере —
  пересоздать `ansible-target1` с `-p 3001:3000`.
